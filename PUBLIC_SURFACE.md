## Reading the matrix

- **Supported configuration check** means an implemented evaluator has a Viewer-compatible input path. It need not perform an offensive operation to be useful.
- **Partial** means an input, predicate, resource variant, or significant source behavior is missing. A generic public-member alert is not an exact data/invocation capability check.
- **Unsupported** distinguishes absent baseline permission, non-GCP/Workspace authority, and deliberately excluded probing/mutation. These are not interchangeable.
- Direct IAM, indexed IAM search, application rules, ACLs, network admission, identity enrollment, and effective runtime access are different evidence. Indexed IAM search is not an exhaustive direct-policy inventory. Missing findings are not proof of safety.
- `allAuthenticatedUsers` is not anonymous. A public grant can still require an accepted token, destination permissions, application authorization, an enabled version, or other service controls.
- Default scans do not brute-force names, create accounts, invoke applications, publish/pull/ack messages, read secret payloads, execute database queries, mount filesystems, or claim resources. DNS resolution is an explicit opt-in. Storage anonymous/content/source scan flags are disabled under this role profile; retained helper code is not an available live scan path.

## Closure boundaries

- **Remaining bounded analysis gaps:** external repository trust correlation using suitably scoped, supplied evidence; Apigee nonliteral/dynamic references and arbitrary/custom condition semantics; App Check target-existence/effective-rule correlation. Firebase metadata and Apigee bounded observed static hook/FlowCallout graphs are implemented, not remaining permission gaps.
- **Unavailable baseline inputs:** direct Storage bucket IAM/ACL and object reads, direct Pub/Sub/IAP policies, Firebase ruleset source, and live Workspace/Looker administration. Existing offline evidence checks remain useful but are not live collection.
- **Unverified permission:** Cloud Run domain-mapping listing stays fail-closed until positive current Viewer permission evidence is available.
- **Outside this tool's configuration-check scope:** account signup, malicious PRs, build execution, task enqueue/run, application invocation, secret/message/database reads, ownership claims and database TCP probes. Missing offensive proof is not itself an implementation defect in a supported configuration detector.
- **External repository trust boundary:** BuildTrigger supplies repository identity, event/comment/approval filters and build-template origin, not repository publicness or a contributor's push/PR rights. Cloud Build Repository `remoteUri` and Source Repositories `mirrorConfig` identify a connection, not external write authorization. Do not invent a `public=true` trust fact from a GitHub URL, installation, or mirror. Stronger offline correlation would require actual provider-exported repository identity/visibility and branch/contributor controls, matched to the observed trigger and collection time. Inline or externally sourced build configuration is not the same as a PR-editable `filename`/autodetected file. [BuildTrigger schema](https://docs.cloud.google.com/build/docs/api/reference/rest/v1/projects.locations.triggers), [connected Repository schema](https://docs.cloud.google.com/build/docs/api/reference/rest/v2/projects.locations.connections.repositories), [Source Repositories schema](https://docs.cloud.google.com/source-repositories/docs/reference/rest/v1/projects.repos).
- **Firebase executable limitation:** `releases.getExecutable` returns base64 bytes with V1 custom-AST or V2 CEL executable formats, not Security Rules source. The reference does not document a source-equivalent JSON grammar; do not treat decoded strings as authoritative open-read/write rules. [Executable API schema](https://firebase.google.com/docs/reference/rules/rest/v1/projects.releases/getExecutable).
- **Apigee remaining analysis:** Viewer permits the implemented hook/shared-flow bundle reads. Native request phases and bounded static dependency chains are summarized; conditions, nonliteral references/custom code and effective enforcement remain unresolved. [Role permissions](https://docs.cloud.google.com/iam/docs/roles-permissions/apigee), [flow hooks](https://docs.cloud.google.com/apigee/docs/api-platform/fundamentals/flow-hooks), [FlowCallout schema](https://docs.cloud.google.com/apigee/docs/api-platform/reference/policies/flow-callout-policy).
