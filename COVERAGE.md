## Enforced authorization boundary

Live native collection is limited to API permissions in the union of `roles/viewer`, `roles/resourcemanager.folderViewer`, and `roles/resourcemanager.organizationViewer`. The runtime guard reads those exact role definitions through fixed IAM GETs, rejects unreviewed methods and nonbaseline permissions before resource requests, and fails closed if it cannot verify the definitions. It does not downscope tokens or prove credential role assignments: use an identity with only these roles, because stronger credentials can expose extra fields on allowed methods. Hierarchy-role grants do not replace project Viewer access.

Current default live discovery covers Resource Manager metadata/project IAM, Compute project/instance/firewall configuration, Storage bucket metadata through no-ACL listing, SQL instances, GKE cluster configuration, Run services/jobs, Functions v1/v2, DNS zones, service-account/key metadata, and project-scoped CAI IAM **search**. CAI `assets.list` RESOURCE/IAM_POLICY is not Viewer-permitted and is no longer the default backbone. Search-only bindings are not complete service configuration, audit configuration, or effective-access evidence. Other services remain an explicitly incomplete discovery backlog.

The new service collectors feed existing SQL/GKE posture and exposure, Run invoker-bypass, configuration-secret, DNSSEC and service-account-key evaluators. Tests cover paginated/partial discovery, denied permissions, malformed and foreign identities, preserved native schemas, key-material omission, and a default-collection-to-report path with payload redaction. No database, Kubernetes, kubelet or workload endpoint is contacted. This improves live evidence coverage, not full source-behavior parity.

The code implements a selected set of measurable configuration indicators from these references, not every technique in the directory. It does not reproduce destructive persistence, exfiltration, privilege-changing API calls, password/2SV resets, phishing or host credential extraction. ## Known collection boundaries

- `--iap-settings` discovers App Engine application/service/version identities and global Compute backends using guarded metadata APIs. BASIC version listing preserves richer supplied configuration. Project/web settings may be read with Viewer; folder/organization settings require distinct permissions and may be denied. Traffic attribution, full deployment metadata and runtime access remain unverified.
- `--iap-policies` now rejects: its separate IAP getIamPolicy permissions are not baseline permissions. The evaluator still reviews supplied/indexed accessor bindings and conditions. Hybrid destination groups, Agent Gateway, forwarding-rule authorization, effective settings, alternate backend routes and reachability remain incomplete. A public accessor binding does not prove successful access.
- `--ancestor-iam` follows parent metadata, but folder/organization getIamPolicy is denied by the role gate. Project allow policies preserve version-3 conditions. Do not claim complete inherited IAM/audit coverage; supplied complete evidence is needed for ancestor calculations. IAM deny, access boundaries, group expansion and condition evaluation remain missing.
- Assigned predefined and custom IAM roles are now resolved and correlated with their direct bindings. The complete local canonical permission-classification snapshot (10,238 permissions) and multi-permission combinations are embedded. Catalog overlap is not full technique coverage: conditions, applicability, group/hierarchy expansion, runtime prerequisites and effective authorization remain unresolved.
- Automation token delivery, Cloud Tasks logging and Artifact Registry upstream-priority checks are implemented. Missing upstream repositories are incomplete coverage. Task payload enumeration and consumer package-resolution behavior remain outside current collection.

- Default Viewer discovery uses direct service APIs plus project-scoped CAI IAM search, not full CAI resource exports. An IAM-only record cannot support settings checks. Search preserves indexed bindings and conditions but is eventually consistent and limited to supported types; search-only policies are marked bindings-only so omitted audit fields are not interpreted as disabled controls.
- Compute project/instance metadata, global/regional instance templates and machine-image metadata are collected directly. Failed scopes and missing properties remain incomplete. Other service configuration needs supplied evidence until its Viewer-compatible collector exists.
- IAM key metadata can be refreshed only for discovered account identities and where the guarded list permission and target authorization permit. The current discovery path does not guarantee complete service-account enumeration. Search and direct reads are not an atomic snapshot.
- Logging sink exclusions are evaluated from sink metadata. `--logging-config` refreshes sinks, standalone exclusions and all-location bucket metadata. Bucket indicators review explicit one-day retention, lock, pending deletion and field restrictions without claiming malicious changes or lost records. Discovered in-scope bucket views receive metadata and direct version-3 IAM reads; filter semantics, historical changes and effective access remain unverified. Sink collection continues with ancestor intercepting sinks included by the API's ALL filter. Route checks review aggregated/intercepting sinks and storage/PubSub/BigQuery exports, but do not establish destination ownership, readers, write authorization or successful delivery. Project metric metadata and discovered-bucket links are also listed. Explicit disabled metrics and ACTIVE linked datasets are configuration indicators only; filter semantics, historical deletion, dependent alerts and effective BigQuery access remain unverified. Non-intercepting ancestor sinks outside selected/discovered scopes require further collection.
- Default discovery enumerates known public/private DNS record metadata; address lookup still requires `--dns-checks`. Negative answers can reflect resolver/propagation conditions, not claimability.
- Secret detection is heuristic and value-redacted. It does not validate tokens. Unrecognized formats, encoded values or missing resource fields can be missed.
- GCS object/source content and list-backed anonymous probes are disabled live. Existing bounded scanners/evaluators do not count as Viewer-compatible collection. Logging remains role-gated and bounded by window/page/entry limits; private Data Access/Access Transparency logs are excluded, including conservative externalaudit variants. Special views/restricted fields are not covered by the role guarantee, and stronger credentials are not downscoped by the method guard. No image/repository/version-history coverage or full external detector parity is claimed.
- All Workspace collection is disabled: GCP Viewer roles grant no Directory/Groups Settings authority. Supplied users/groups/membership/admin/OAuth/DWD/Gmail/Drive records remain evaluable offline; obtaining those records is not claimed as a Viewer capability. No complete nested-group privilege graph is built.
- Native findings never persist collected secret values or complete resource bodies. Evidence still contains resource identifiers, principal names and policy metadata. Keep engagement directories private.
- The dashboard preserves four categories, but the AWS Bubble Tea UI, Docker fallback, SQS monitor and AWS-specific flags are not retained. The GCP CLI provides live progress lines, standalone HTML/JSON, SQLite, local serving, and fingerprint-checked resume.

Live grant evidence comes from indexed CAI IAM search and resolved roles; direct topic/subscription IAM reads are unavailable under the three-role boundary. Conditions, index completeness and effective authorization remain unresolved. No messages are published, pulled, acknowledged or replayed, and attachment alone does not prove subscription creation or consumption.

Further Pub/Sub coverage: schema and revision lists require explicit `view=BASIC` and locally omit definitions; snapshots retain only name, topic reference and expiration. Subscription projection now omits transforms, labels, filter contents and unknown fields. Best Practices flags only explicit `detached: true` or the exact `_deleted-topic_` marker. IAM & Access reports explicitly configured export writers/destinations for BigQuery, Cloud Storage and Bigtable, without inferring a default identity or effective write access. Conservative identifier validation can omit unusual export identities/names. No mutation, message access or replay is permitted. Historical changes, destination ownership, import-source configuration, service-specific audit coverage and full technique correlation remain gaps. The allowed list permissions are documented in [Pub/Sub roles](https://docs.cloud.google.com/iam/docs/roles-permissions/pubsub), and state/export fields in the [Subscription API](https://docs.cloud.google.com/pubsub/docs/reference/rest/v1/projects.subscriptions).

Instant/recoverable snapshots, recycle-bin policies, database-backup sharing and effective inherited authorization remain gaps. Allowed direct policy permissions are documented in [Compute IAM](https://docs.cloud.google.com/iam/docs/roles-permissions/compute); source-use prerequisites are documented in [disk creation](https://docs.cloud.google.com/compute/docs/reference/rest/v1/disks/insert).
